## Data and persistence

A fresh browser context starts from catalog fixtures. Do not depend on an evaluator-specific IndexedDB object-store layout.

All business records have stable string `id`, `workspaceId`, and local integer `revision>=1`. IDs are unique within each entity type across workspaces. A record belongs to exactly one workspace. IDs/references are transferred through exports or generated by the UI; normal forms use readable service/release names rather than asking people to type IDs or JSON.

- Service: `{id,workspaceId,name,owner,runbookMarkdown,archived,revision}`. Name1..100, owner1..100, runbook<=10000characters, archived boolean. Names are case-insensitively unique within a workspace. Create/edit/archive services; keep archived services readable in existing releases and exclude them from new selections. Archiving never silently deletes linked records.
- Release: `{id,workspaceId,title,version,serviceIds,dependsOn,effortMinutes,checklist,status,notesMarkdown,revision}`. Title1..120 unique case-insensitively per workspace; version1..40; one or more unique service IDs; zero or more unique dependency release IDs; integer effort1..480; checklist `{id,label,done}` with stable item IDs, label1..160, boolean done; status `draft|approved|shipped`; notes<=10000characters. Create/edit draft releases and manage checklist items. Shipped releases are read-only. Only unreferenced draft releases can be deleted, after confirmation. Invalid edits are atomic and show a visible error.
- Incident: `{id,workspaceId,title,serviceIds,severity,status,summary,timeline,revision}`. Title1..120, nonempty unique service IDs, severity `low|medium|high|critical`, status `open|resolved`, summary<=10000characters. Timeline entries `{id,at,actor,body}`, body1..2000, have actual ISO8601 timestamps and the current local actor **Alex Morgan**. Create/edit/resolve incidents; append visible timeline updates; retain prior entries on resolution.
- Audit event: `{id,workspaceId,at,actor,action,entityId}`. Append once after successful local mutations, imports, approval and shipping. Failed edits/imports/readiness requests produce no fake success event. Show real actor, human-readable action and timestamp. Retain a bounded recent history of at least1000events. Use IndexedDB transactions for mutations and snapshot replacement. Do not lose unrelated edits from another open tab. ## Stateless API contract

All JSON responses have `policyVersion`, exact Git `deployedSha` and nonempty sanitized top-level `requestId`, with `Cache-Control:no-store`. Health returns `{status:"ok",nodeMajor:24,policyVersion,deployedSha,requestId}`. Catalog adds `workspaces,services,releases,incidents,limits:{maxEntitiesPerType:200,maxBodyBytes:262144}`. No tokens, private environment or stacks appear in responses.

POST payloads contain `{workspaceId,services,releases,incidents}` and a target `releaseId` for validation or nonempty unique `releaseIds` for simulation. Supply the complete selected-workspace snapshot, at most200records per type. All records/references belong to that workspace; malformed, duplicate, missing required fields or impossible enum/number/boolean values fail. Display metadata and local revisions may be supplied but do not affect the operation hash. Unknown target release404; body/schema400, foreign workspace400, non-JSON415, body>262144bytes413, unsupported method405. Error shape is `{error:{code,message,requestId},requestId,policyVersion,deployedSha}`; nested and top-level request IDs match. Use codes `INVALID_INPUT`, `FOREIGN_WORKSPACE`, `RELEASE_NOT_FOUND`, `UNSUPPORTED_MEDIA_TYPE`, `PAYLOAD_TOO_LARGE`, `METHOD_NOT_ALLOWED` as applicable.

`POST /api/validate-release` returns200 `{valid,blockingReasons,policyVersion,deployedSha,requestId}`. Reasons are unique `{code,entityId,message}`, sorted by code then entityId. Human-readable messages explain actual causes. The following block readiness:

| Condition | Code / entityId |
| --- | --- |
| Incomplete checklist item | `CHECKLIST_INCOMPLETE` / checklist item ID |
| Unknown or archived selected service | `UNKNOWN_SERVICE` or `ARCHIVED_SERVICE` / service ID |
| Unknown dependency | `UNKNOWN_DEPENDENCY` / dependency ID |
| Self dependency or dependency cycle | `SELF_DEPENDENCY` or `CYCLIC_DEPENDENCY` / target release ID |
| Direct dependency not shipped | `DEPENDENCY_NOT_SHIPPED` / dependency ID |
| Open high/critical incident sharing a target service | `BLOCKING_INCIDENT` / incident ID |
| Target already shipped | `ALREADY_SHIPPED` / target release ID |

Unrelated-workspace records are rejected rather than used. Unrelated-service, resolved, low and medium incidents do not block. No reasons means valid. **Check readiness**, **Approve release** and **Ship release** use real current-snapshot hosted validation. A500, offline request or `valid:false` must not approve/ship. Revalidate on approval/shipping and do not trust a stale prior green result after checklist, dependency, service or incident changes. Draft→approved→shipped are the only forward transitions. Shipped dependencies unblock their dependents.

`POST /api/simulate-rollout` returns200 `{stages,totalEffortMinutes,operationHash,policyVersion,deployedSha,requestId}`. For each selected release, all readiness rules apply except a dependency also selected may be unshipped and is scheduled first. An outside-selected dependency must already be shipped. Reject unknown, cyclic or blocked plans; business rejection409 `SIMULATION_BLOCKED` with actual `blockingReasons`. Each stage `{index,releaseIds,effortMinutes}` is a Kahn topological level, index starting1, release IDs sorted lexicographically. Stage effort is the sum of releases in that level; total is the exact sum once per selected release. Never mutate any release while simulating.

`operationHash` is lowercase SHA256 of UTF8 compact JSON, with every object key recursively sorted, for:

```text
{policyVersion:"releaseops-v1",workspaceId,releaseIds:sorted,
 services:sortById[{id,workspaceId,archived}],
 releases:sortById[{id,workspaceId,serviceIds:sorted,dependsOn:sorted,effortMinutes,
   checklist:sortById[{id,done}],status}],
 incidents:sortById[{id,workspaceId,serviceIds:sorted,severity,status}]}
```

Normalize entity/ID-set order, preserve actual semantic values. Titles, versions, owner/runbook/notes/timeline/actor/local revisions, request IDs and deployment SHA are excluded. Reordering arrays or editing a note does not change the hash; changing semantic state does. Parallel requests are independent, and repeated equivalent snapshots yield identical operation results/hash.
